# Полный аудит sitkaz — 5 августа 2026

Мини-приложение для изучения разговорного казахского (Next.js 16 / React 19, Telegram Mini App + PWA). Аудит охватывает путь клиента, работоспособность и код/архитектуру/безопасность. Живое приложение: `https://sitkaz-kz.vercel.app`.

---

## Краткий вывод

Код приложения — крепкий и аккуратный: чистая архитектура обучения, продуманный UX, корректная авторизация Telegram, хорошая гигиена секретов и базы. Целостность контента идеальная (860 фраз, все с озвучкой, без битых ссылок и дублей). Все исходники синтаксически валидны.

Есть один нестабильный момент на пути клиента: **прод-адрес на Vercel периодически отдаёт полноэкранное предупреждение Chrome**. При первой проверке приложение не открывалось; при повторной — открылось нормально, воронка прошла целиком без ошибок. То есть блокировка прерывистая, а не постоянная, но даже эпизодически она отсекает часть пользователей на нулевом шаге. Плюс два продуктовых пробела: нет аккаунтов/синхронизации вне Telegram и нет способа брать оплату.

Живой проход подтверждён: онбординг (3 шага) → главная курса → урок с карточками и озвучкой работают корректно, ошибок в консоли нет (единственное сообщение — безобидное «CloudStorage is not supported in version 6.0» от Telegram SDK в обычном браузере, оно заглушено проверкой в коде).

## 🔴 Критично

**1. Прод-деплой периодически отдаёт браузерное предупреждение.**
При первой проверке переход на `https://sitkaz-kz.vercel.app` давал полностраничный интерстишл Chrome «Предупреждение» — страница не открывалась и не поддавалась взаимодействию. При повторной проверке через несколько минут приложение открылось нормально и весь путь клиента прошёл без ошибок. Значит, блокировка **прерывистая**. Публичный список Google Safe Browsing по домену при этом чист («No available data») — то есть это, скорее всего, эвристическая/real-time блокировка, типичная для «голых» поддоменов `*.vercel.app`, а не подтверждённое попадание в чёрный список.

Почему это важно: даже эпизодическое предупреждение отсекает часть пользователей (особенно переходящих из Telegram или по ссылке) на нулевом шаге — они видят красный экран и уходят. Прерывистость к тому же затрудняет диагностику.

Что делать: **подключить собственный домен** (например `app.sitkaz.kz`) вместо `*.vercel.app` — собственные домены почти не ловят эту эвристику; проверить открытие на нескольких реальных устройствах и сетях; если предупреждение будет повторяться — запросить проверку в Google Search Console и проверить статус деплоя в Vercel.

## 🟠 Существенно

**2. Нет аккаунтов и синхронизации вне Telegram.**
В обычном браузере прогресс живёт только в `localStorage` этого устройства. Очистка кэша или переход на другой телефон/компьютер = потеря прогресса. Серверная синхронизация (Supabase) работает только внутри Telegram, где есть подписанный `initData`. Логика слияния данных сделана аккуратно (без затирания), но само хранилище вне Telegram — одноразовое. Для удержания это реальный риск. В roadmap это признано, но пока не закрыто.

**3. Нет пути монетизации.**
Все модули и уроки открыты (`moduleUnlocked = () => true`), промокод и платный доступ убраны (видно в истории git: «убрать промокод, открыть доступ ко всем урокам»). Для платного курса сейчас нет механизма ограничить доступ или взять оплату. Это продуктовый/бизнес-пробел, а не баг — но его стоит закрыть до запуска монетизации.

**4. Очень свежие зависимости (Next 16.2.11, React 19.2.4, сборка через Turbopack).**
Это «передний край», выше риск регрессий и нестабильности сборки. Локальная сборка в песочнице упала с bus error — это, скорее всего, ограничение окружения, а не код (все файлы парсятся, приложение задеплоено). Рекомендация: убедиться, что `npm run build` стабильно проходит в CI/Vercel, и зафиксировать версии (сейчас в `package.json` они без диапазонов — это хорошо, но проверьте, что lock соответствует прод-сборке).

## 🟡 Средне

**5. Расхождение в документации о размере курса.**
`README.md` говорит «14 модулей, 41 урок» и называет фразы «структурным скелетом», а по факту курс — **6 модулей, 20 уроков, 860 реальных фраз** (kk/ru/en/транслитерация) с озвучкой. Комментарий в `lib/game.js` тоже упоминает «14 тем». README вводит в заблуждение — стоит обновить. Также в README «реальные тексты и видео» числятся в TODO: проверьте, что поля `video` в уроках заполнены (задел под видео-лекции присутствует в коде).

**6. Фильтры к Supabase собираются конкатенацией строк.**
В `lib/supabase.js`: `progress?telegram_id=eq.${telegramId}`. Значение — числовой `id` уже проверенного Telegram-пользователя, поэтому риск инъекции низкий, но собирать REST-фильтры интерполяцией — плохая привычка. Оберните в `encodeURIComponent` или используйте официальный клиент.

**7. Нет ограничения частоты запросов (rate limiting) на API-роутах.**
Авторизованный пользователь Telegram может слать много запросов к `/api/progress`. Риск невелик, но лимит не помешает.

## Что сделано хорошо (сохранить)

**Безопасность Telegram:** подпись `initData` проверяется правильно — HMAC-SHA256 по документации, сравнение за постоянное время (`timingSafeEqual`), проверка свежести (24 часа). Подделать чужой `telegram_id` не выйдет.

**Секреты:** в git ничего не утекло, отслеживается только `.env.example`. Service-role ключ Supabase используется строго на сервере. `.env*` в `.gitignore`.

**База данных:** RLS включён на обеих таблицах без публичных политик (анонимный ключ не получит ничего), доступ только через служебный ключ на сервере; сводное представление `progress_overview` с `security_invoker` и отозванными правами для `anon/authenticated`. Чисто.

**Целостность данных:** 6 модулей / 20 уроков / 860 фраз; у всех 860 фраз есть озвучка; битых ссылок на аудио — 0; дублей id уроков — нет; у всех фраз заполнены kk/ru/tr.

**Локализация:** RU/EN в полном паритете (по 122 ключа, расхождений нет).

**Учебный цикл и UX:** онбординг → изучение карточек с аудио → практика (4 типа заданий, включая сборку фразы) → экзамен темы → интервальное повторение (система Лейтнера) → геймификация (XP как «высота», уровни, серии, достижения, «настроение» маскота). Плюс мелочи заботы: доступность с клавиатуры, аудио-дружественные переходы (не режут звук), offline-first хранилище с аккуратным слиянием без потери данных.

## Путь клиента (по коду)

Первый вход в браузере: заставка → онбординг (приветствие + первое слово с озвучкой → «зачем учишь» → цель на день) → главная (кольцо цели, маскот Ирбис, серия и XP, кнопка «продолжить», блок повторений, список тем — все открыты) → тема → урок (изучение → практика → готово; опционально диалог-сценка) → экзамен темы → практика (повторение SRS + квиз) → прогресс (уровень, серия, достижения, «добавить на главный экран»).

Разрывы на пути: (а) нулевой шаг блокирует предупреждение браузера (п.1); (б) в браузере нет персонализации по имени и нет входа; (в) прогресс держится на `localStorage`.
